# WebSocket 재생 신호 연동 프로토콜

## 0. 확정 예정 값 

| 항목 | 값 |
|---|---|
| 접속 주소 | `ws://192.168.8.10:3000/playback-control` |
| 인증 | 접속 시 파라미터로 공유 토큰 (구현과정에서 생성하여 전달 예정): `?token=<SHARED-TOKEN>` |
| 전송 방식 | WebSocket (텍스트 프레임, UTF-8 JSON) |

## 1. 시스템 개요

```
디스플레이 컨트롤 미디어 시스템 ──WebSocket──▶ 구체 오브제 서버 ──MQTT──▶ 폰 439대
```

## 2. 연결 방법

1. 미디어 시스템이 위 주소로 WebSocket 연결을 시작합니다(토큰을 쿼리
   파라미터에 포함).
2. 토큰이 없거나 틀리면 서버가 연결을 즉시 종료합니다(close code 협의 필요,
   예: 4001 = 인증 실패).
3. 연결이 끊기면 미디어 시스템이 재연결을 시도해야 합니다(서버는 재연결
   시점에 이전 상태를 다시 보내주지 않습니다 - 3번 참고).

## 3. 메시지 형식

### 3-1. 미디어 → 서버 (재생 신호)

```json
{ "type": "PLAY_TRIGGER" }
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `type` | string | 항상 `"PLAY_TRIGGER"` |

수신 즉시 서버가 재생을 시작합니다(추가 파라미터 없음 - 특정 영상을
지정하는 기능이 아니라 "지금 배포된 영상을 지금 재생하라"는 단순 트리거).

### 3-2. 서버 → 미디어 (응답)

성공:
```json
{ "type": "ACK", "received": "PLAY_TRIGGER", "startAt": 1755300000123 }
```

실패(형식 오류 등):
```json
{ "type": "ERROR", "message": "알 수 없는 type입니다: ..." }
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `startAt` | integer | 실제 재생이 시작되는 서버 epoch ms - 참고용(미디어 쪽에서 카운트다운 UI 등에 쓸 수 있음) |

## 4. 에러 처리 / 재시도

- 서버는 동일 신호를 짧은 간격으로 여러 번 받아도 안전합니다(이미 재생
  중이면 그냥 다시 시작 - 폰 쪽 동작은 `/api/play`와 동일).
- 네트워크 단절 시 미디어 시스템이 재연결하는 것을 권장합니다. 재연결
  실패가 반복되면 알람을 울리는 등은 미디어 시스템 쪽에서 처리해주세요.

## 5. 네트워크 주의사항

- 5GHz 폐쇄망 내부 전용으로 설계됩니다 - 인증 토큰이 있긴 하지만 TLS는
  적용되어 있지 않습니다(폐쇄망 전제). 외부 인터넷 경유가 필요하면 별도
  협의가 필요합니다.
- 같은 서버(192.168.8.10)의 포트 3000을 REST API/대시보드와 공유합니다.

## 6. 확인이 필요한 사항 (미디어 협의용 체크리스트)

- [ ] 미디어 시스템이 WebSocket 클라이언트 구현이 가능한지 (프로토콜 확정
      전 이 부분부터 확인 필요)
- [ ] 정지(STOP_TRIGGER) 신호도 필요한지
- [ ] 재생 신호에 특정 영상 지정이 필요한지, 아니면 항상 "지금 배포된
      영상 재생"으로 충분한지
- [ ] 인증 토큰 값 확정 및 전달 방법(어떻게 안전하게 공유할지)
- [ ] 연결 경로(`/playback-control`) 확정
- [ ] 재연결 시 서버가 현재 상태(재생 중/정지)를 알려줘야 하는지, 아니면
      트리거 신호만 주고받으면 되는지
