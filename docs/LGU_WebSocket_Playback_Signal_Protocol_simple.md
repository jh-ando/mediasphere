# WebSocket 재생 신호 연동 프로토콜 (초안 - 단순화 버전)

## MediaSphere 서버 재생 트리거 연동
대상: 외부 디스플레이 컨트롤 업체

**주의: 이 문서는 초안입니다.** 인증 없이, PLAY 신호 하나만 받는 가장
단순한 구성입니다 - 폐쇄망 내부에서만 접속 가능하다는 전제로 인증을
생략했습니다. 아래 내용을 바탕으로 업체와 협의 후 확정합니다 - 지금은
서버에 구현되어 있지 않습니다.

(토큰 인증 + STOP 신호까지 포함한 버전은
`LGU_WebSocket_Playback_Signal_Protocol.md` 참고)

## 0. 확정 예정 값 (협의 필요)

| 항목 | 값 |
|---|---|
| 접속 주소 | `ws://192.168.8.10:3000/playback-control` (경로는 협의 가능) |
| 인증 | 없음 - 폐쇄망 내부에서만 접근 가능한 걸 전제로 함 |
| 전송 방식 | WebSocket (텍스트 프레임, UTF-8 JSON) |

MediaSphere 대시보드가 이미 같은 포트(3000)에서 WebSocket을 쓰고 있으나
그건 대시보드 전용 상태 브로드캐스트 채널이고, 이 문서의 연동은 **별도
경로의 새 채널**입니다 - 같은 연결을 공유하지 않습니다.

## 1. 시스템 개요

```
디스플레이 컨트롤 업체 시스템 ──WebSocket──▶ MediaSphere 서버 ──MQTT──▶ 폰 439대
                                                                (기존 /api/play와 동일 경로)
```

업체 시스템이 재생 트리거 신호를 보내면, MediaSphere 서버는 기존
`/api/play`가 하는 것과 동일하게 재생 시작 시각(`startAt`)을 계산해서
MQTT `PLAY` 명령을 439대 폰에 발행합니다. 정지는 이 채널로 다루지
않습니다(필요해지면 별도 협의).

## 2. 연결 방법

1. 업체 시스템이 위 주소로 WebSocket 연결을 시작합니다(별도 인증 절차
   없음).
2. 연결이 끊기면 업체 시스템이 재연결을 시도해야 합니다 - 서버는 재연결
   시점에 이전 상태를 다시 보내주지 않습니다.

## 3. 메시지 형식

### 3-1. 업체 → 서버 (재생 신호)

```json
{ "type": "PLAY_TRIGGER" }
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `type` | string | 항상 `"PLAY_TRIGGER"` |

수신 즉시 서버가 재생을 시작합니다(추가 파라미터 없음 - 특정 영상을
지정하는 기능이 아니라 "지금 배포된 영상을 지금 재생하라"는 단순 트리거).
이 신호 외 다른 타입(정지 등)은 이 연동에서 다루지 않습니다.

### 3-2. 서버 → 업체 (응답)

성공:
```json
{ "type": "ACK", "received": "PLAY_TRIGGER", "startAt": 1755300000123 }
```

실패(형식 오류 등):
```json
{ "type": "ERROR", "message": "알 수 없는 type입니다: ..." }
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `startAt` | integer | 실제 재생이 시작되는 서버 epoch ms - 참고용(업체 쪽에서 카운트다운 UI 등에 쓸 수 있음) |

## 4. 에러 처리 / 재시도

- 서버는 동일 신호를 짧은 간격으로 여러 번 받아도 안전합니다(이미 재생
  중이면 그냥 다시 시작 - 폰 쪽 동작은 `/api/play`와 동일).
- 네트워크 단절 시 업체 시스템이 재연결하는 것을 권장합니다. 재연결
  실패가 반복되면 알람을 울리는 등은 업체 시스템 쪽에서 처리해주세요.

## 5. 네트워크 주의사항

- 5GHz 폐쇄망 내부 전용으로 설계됩니다 - 인증이 없는 열린 채널이라
  네트워크에 연결되는 모든 장비가 이 신호를 보낼 수 있다는 전제로
  설계됩니다.
- 같은 서버(192.168.8.10)의 포트 3000을 REST API/대시보드와 공유합니다.

## 6. 확인이 필요한 사항 (업체 협의용 체크리스트)

- [ ] 업체 시스템이 WebSocket 클라이언트 구현이 가능한지
- [ ] 연결 경로(`/playback-control`) 확정
- [ ] 인증 없이 진행하는 것에 문제가 없는지(설치 현장이 정말 폐쇄망으로만
      구성되는지 재확인)
