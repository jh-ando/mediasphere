# WebSocket 재생 신호 연동 프로토콜

## 0. 확정 예정 값

| 항목 | 값 |
|---|---|
| 접속 주소 | `ws://192.168.8.10:3000/playback-control` |
| 인증 | 없음 - 폐쇄망 내부에 연결하여 접근 |
| 전송 방식 | WebSocket (텍스트 프레임, UTF-8 JSON) |


## 1. 시스템 개요

```
디스플레이 컨트롤 업체 시스템 ──WebSocket──▶ 구체오브제 서버 ──MQTT──▶ 폰 439대
```

## 2. 연결 방법

1. 미디어 시스템이 위 주소로 WebSocket 연결을 시작합니다(별도 인증 절차
   없음).
2. 연결이 끊기면 미디어 시스템이 재연결을 시도해야 합니다 - 서버는 재연결
   시점에 이전 상태를 다시 보내주지 않습니다.

## 3. 메시지 형식

### 3-1. 미디어 시스템 → 서버 (재생 신호)

```json
{ "type": "PLAY_TRIGGER" }
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `type` | string | 항상 `"PLAY_TRIGGER"` |

수신 즉시 서버가 재생을 시작합니다(추가 파라미터 없음).

### 3-2. 서버 → 미디어 시스템 (응답)

성공:
```json
{ "type": "ACK", "received": "PLAY_TRIGGER", "startAt": 1755300000123 }
```

실패(형식 오류 등):
```json
{ "type": "ERROR", "message": "알 수 없는 type입니다: ..." }
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `startAt` | integer | 실제 재생이 시작되는 서버 epoch ms - (참고용) |

## 4. 에러 처리 / 재시도

- 서버는 동일 신호를 짧은 간격으로 여러 번 받아도 안전합니다(이미 재생
  중이면 그냥 다시 시작)

## 5. 네트워크 주의사항

- 5GHz 폐쇄망 내부 전용으로 설계됩니다
- 같은 서버(192.168.8.10)의 포트 3000을 REST API/대시보드와 공유합니다.
