# 02. 설치·구축 런북

> 처음부터 다시 세팅하거나 서버·폰을 교체할 때 이 순서대로 따라 하면 되도록 정리한 문서입니다.
> 운영(대시보드 조작)은 운영 매뉴얼 v2(`00_Admin/소소익선_운영_매뉴얼_v2.pdf`), 장애 대응은 [05_장애대응_가이드](05_장애대응_가이드.md)를 참고하세요.
> 표시: ⚠ = 실수하면 복구가 번거로운 단계, 📝 = 현장 값을 확인해서 채워야 하는 항목

---

## 0. 전체 순서

```
① 네트워크(AP 10대, 5GHz 폐쇄망)  →  ② 운영 서버(Ubuntu)  →  ③ 영상 준비·배포 폴더
→  ④ 폰 초기 세팅(1대씩: Wi-Fi·APK·Device Owner·config)  →  ⑤ 구체 설치  →  ⑥ 첫 배포·재생 확인
```

---

## 1. 네트워크

| 항목 | 값 |
|---|---|
| 서버 IP | `192.168.8.10` (고정) |
| 대역 | 5GHz 전용, 인터넷 연결 없는 폐쇄망 |
| AP | 10대, SSID `MEDIA_01` ~ `MEDIA_10` |
| 폰 배정 | deviceId 순서대로 연속 블록: AP 1~9번은 44대씩, 10번은 43대 (`gen_manifest.py`의 `assign_ssids`) |
| 멀티캐스트 | `239.0.0.1:5000` UDP. 스위치·AP에서 멀티캐스트가 막히지 않아야 함(IGMP snooping 설정 확인) |
| 포트 | 서버 TCP 3000(HTTP/WebSocket), 1883(MQTT) |

- 📝 AP별 실제 설치 위치, 채널 배정, 관리자 접속 주소는 [07_하드웨어_설치기록](07_하드웨어_설치기록.md)에 기록합니다.
- config.json의 `ssid`는 **기록용**입니다. 앱이 이 값으로 Wi-Fi에 붙지 않으므로 폰마다 Wi-Fi를 직접 연결해야 합니다(4.2).
- 폰 배치 순서와 AP 블록이 맞아야 물리적으로 가까운 폰들이 같은 AP를 씁니다.

## 2. 운영 서버 (Ubuntu 24.04)

### 2.1 필요한 것

| 구성 | 용도 | 확인 명령 |
|---|---|---|
| Node.js 20 LTS | 마스터 서버 | `node -v` (운영 v20.20.2 확인됨) |
| Mosquitto | MQTT 브로커 | `systemctl is-enabled mosquitto` |
| Python 3.11+ | 영상 분할 파이프라인(대시보드 영상 교체가 `python3`로 호출) | `python3 --version` |
| FFmpeg (NVENC 지원) + NVIDIA GPU·드라이버 | 대시보드 영상 교체가 `hevc_nvenc`, 동시 10개로 인코딩 | `ffmpeg -encoders \| grep nvenc`, `nvidia-smi` |
| 디스크 여유 | 영상 교체 중에는 배포 폴더 두 벌(현재 + `.staging`) + 업로드 원본(최대 8GB) | `df -h` |
| 전원 모드 **퍼포먼스** 고정 | 밸런스 모드면 타임코드가 늦어져 동기화가 틀어짐 | 설정 → 전원 |

### 2.2 설치

```bash
sudo apt update
sudo apt install -y mosquitto mosquitto-clients python3 ffmpeg git
# Node.js 20은 NodeSource 또는 nvm으로 설치 (nvm이면 node 절대경로가 사용자 폴더 아래가 됨)
```

Mosquitto는 외부(폰)에서 붙을 수 있어야 합니다. Mosquitto 2.x는 기본값이 "localhost만, 익명 불가"이므로 설정 파일을 추가합니다.

```bash
sudo tee /etc/mosquitto/conf.d/mediasphere.conf >/dev/null <<'EOF'
listener 1883 0.0.0.0
allow_anonymous true
EOF
sudo systemctl restart mosquitto
```

> 인증 없음은 폐쇄망을 전제로 한 결정입니다(기술 부채, [01_개발_정리](01_개발_정리.md) 4장).
> 📝 운영 서버의 실제 conf 내용이 위와 다르면 이 문서를 고쳐 주세요.

### 2.3 코드 받기

```bash
cd /home/mediasphere
git clone <저장소 주소> MediaSphere        # 📝 저장소 주소
cd MediaSphere/server
npm ci
```

- `server/data/`(운영 설정), `server/distribute/`(배포 영상), `server/apk/`, `server/uploads/`는 git에 없습니다. 서버를 옮길 때는 **`data/`와 `distribute/`를 그대로 복사**하세요.
- `pipeline/slicer/base-config.example.json`의 `serverIp`·`mqttBroker`가 실제 서버 IP와 같아야 합니다. 대시보드 영상 교체가 이 파일로 폰 config를 만듭니다.

### 2.4 자동 실행 (systemd)

```bash
sudo tee /etc/systemd/system/mediasphere-server.service >/dev/null <<'EOF'
[Unit]
Description=MediaSphere Server
After=network-online.target mosquitto.service
Wants=network-online.target

[Service]
User=mediasphere
WorkingDirectory=/home/mediasphere/MediaSphere/server
ExecStart=/usr/bin/node src/server.js
Restart=always
RestartSec=3
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now mediasphere-server
```

- `ExecStart`의 node 경로는 `which node` 결과로 바꿉니다(nvm 설치 시 특히 주의).
- 📝 운영 서버에 이미 등록된 유닛 이름이 다를 수 있습니다. `systemctl list-units --type=service | grep -i media`로 확인한 뒤 이 문서를 실제 이름으로 고쳐 주세요.
- 로그 보기: `journalctl -u mediasphere-server -f`

### 2.5 코드 업데이트

```bash
cd /home/mediasphere/MediaSphere && git pull
sudo systemctl restart mediasphere-server    # server/src, server/lib가 바뀌었을 때
```

- `server/public/`(대시보드 화면)만 바뀌었으면 재시작 없이 브라우저 새로고침만 하면 됩니다.
- ⚠ **재생·배포·영상 교체 중에는 재시작하지 마세요.** 진행 중인 배포 상태는 메모리에만 있습니다.

### 2.6 대시보드 자동 표시 (선택)

서버 PC 모니터에 대시보드를 띄워 두려면 그래픽 세션의 "시작 프로그램"에 `firefox --kiosk http://localhost:3000`을 등록합니다.

### 2.7 서버 동작 확인

```bash
curl http://localhost:3000/api/time            # {"serverMs":...}
curl http://localhost:3000/api/state
mosquitto_sub -h localhost -t 'wall/status/#' -C 3    # 폰 heartbeat 3개 수신
```

## 3. 영상 준비와 배포 폴더

평소에는 **대시보드 [영상 교체]**로 업로드하면 타일 계산 → 인코딩 → 배포가 자동으로 진행됩니다(운영 매뉴얼 참고). 서버를 새로 세팅했거나 대시보드를 쓸 수 없을 때만 아래 수동 절차를 씁니다.

```bash
cd /home/mediasphere/MediaSphere/pipeline/slicer
# 1) 타일 좌표 (구체, 등장방형 4096x2048 기준 + 설치 회전 보정 22.5°)
python3 gen_tiles.py sphere --source 4096x2048 --lon-offset 22.5 -o tiles/sphere439.json
#    일반 1:1 영상을 전/후면에 씌우려면: --source 2160x2160 --front-back
# 2) 분할·인코딩·manifest·config를 한 번에 (-o는 주지 말 것 - 기본값이 server/distribute)
python3 deploy.py -i master.mp4 -t tiles/sphere439.json \
  --ap-count 10 --base-config base-config.example.json --encoder hevc_nvenc -j 10
```

결과물: `server/distribute/{videos/*.mp4, manifest.json, configs/*.json}`. 그다음 대시보드에서 배포하거나 `curl -X POST http://localhost:3000/api/distribute/publish`를 호출합니다.

> 원본 해상도가 바뀌면 tiles.json을 **반드시 다시 생성**합니다(좌표가 원본 해상도 기준으로 고정되어 있음). 자세한 내용은 CLAUDE.md의 "영상 분할 표준 워크플로우"를 보세요.

## 4. 폰 초기 세팅 (1대씩)

### 4.1 준비물
- PC에 adb(Android SDK platform-tools), 레포의 `pipeline/slicer/push_config.py`, release APK
- `server/distribute/configs/{deviceId}.json` (3장에서 생성)
- 폰 뒷면 deviceId 라벨 (📝 라벨 규칙은 07 문서)

### 4.2 순서

| # | 작업 | 방법 / 확인 |
|---|---|---|
| 1 | **초기화 상태 확인** | ⚠ Device Owner는 **Google/Samsung 계정이 하나도 없어야** 등록됩니다. 계정을 추가하지 말고 초기 설정을 건너뜁니다 |
| 2 | 개발자 옵션 + USB(또는 무선) 디버깅 켜기 | 설정 → 휴대전화 정보 → 소프트웨어 정보 → 빌드번호 7번 탭 |
| 3 | 화면 세팅 | 화면 자동 꺼짐 최대, 화면 잠금 **없음**, 자동 회전 끔, 절전 모드·적응형 배터리 끔, 자동 업데이트 끔 |
| 4 | **날짜·시간 자동 설정 켜기** | ⚠ 시계가 크게 틀린 폰은 텍스트 스크롤 싱크가 어긋남(실제 사례: 시계가 몇 달 틀린 폰) |
| 5 | Wi-Fi 연결 | 그 폰 deviceId가 속한 AP(`MEDIA_xx`)에 연결. 다른 SSID는 저장하지 않음 |
| 6 | APK 설치 | `adb install -r app-release.apk` (⚠ 반드시 **release 서명** APK. 디버그 APK를 깔면 이후 OTA가 서명 불일치로 실패) |
| 7 | **Device Owner 등록** | `adb shell dpm set-device-owner com.mediasphere.client/.DeviceAdminReceiver` → `Success` 확인 |
| 8 | 모든 파일 접근 권한 | 앱 첫 실행 때 뜨는 설정 화면에서 허용. 또는 `adb shell appops set --uid com.mediasphere.client MANAGE_EXTERNAL_STORAGE allow` |
| 9 | config 넣기 | `python3 push_config.py <deviceId>` (여러 대를 순서대로: `--sequential --start-id N`) |
| 10 | 앱 실행 → 번호 확인 | 실행 직후 5초 동안 deviceId가 크게 표시됨. 라벨과 같은지 확인 |
| 11 | 대시보드 확인 | 그리드에서 그 번호 칸이 온라인(초록)으로 바뀌는지 확인 |

- 7번까지 끝나면 앱이 **키오스크 잠금 + 고정 홈 앱**으로 동작합니다. 앱이 죽어도 시스템이 다시 띄우고, 재부팅하면 자동 실행됩니다.
- 이후 config·영상 갱신은 MQTT(`wall/device/{id}`, retain)로 자동 처리되므로 `push_config.py`는 처음 한 번만 씁니다.
- 현장 정비: 화면 왼쪽 위 구석을 빠르게 5번 탭하면 정비 메뉴([설정 열기]/[앱으로 돌아가기])가 나옵니다. 10분이 지나면 자동으로 앱으로 돌아갑니다.

### 4.3 이미 세팅된 폰을 다른 번호로 바꿀 때
`push_config.py <새 번호>` → 대시보드 [앱 재시작] → 화면에 새 번호가 뜨는지 확인. Wi-Fi AP도 새 번호 블록에 맞게 바꿉니다.

### 4.4 Device Owner 해제가 필요할 때
앱 설정에서는 해제할 수 없습니다. 공장 초기화가 가장 확실합니다. 초기화한 뒤 4.2를 처음부터 다시 진행합니다.

## 5. 구체 설치 시 확인

- 번호 규칙: 경도 0°, 위도 +64.29° 행이 1번이고 행 안에서는 동쪽으로 증가, 위도가 높은 행부터 차례로(CLAUDE.md 배치표). 폰은 **전부 세로 방향**.
- 위도별 대수와 번호 범위는 [07_하드웨어_설치기록](07_하드웨어_설치기록.md)의 표를 따릅니다.
- 설치가 물리적으로 회전돼 있으면 영상 방향은 `--lon-offset`(현재 22.5°)으로 보정합니다. 폰 번호는 바꾸지 않습니다.
- 전원: 전 기기 상시 USB 전원. 대시보드 "미충전" 알림은 케이블 불량 신호입니다.
