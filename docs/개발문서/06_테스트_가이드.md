> 실기기 439대 없이 어디까지 검증할 수 있는지, 그리고 그 방법을 정리했습니다.
> 도구는 `tools/test/`에 있습니다. 개발 중에는 세션 임시 폴더에서 쓰던 것을 레포로 옮기면서 경로만 레포 기준으로 바꿨습니다.

## 1. 검증 단계

| 단계 | 도구 | 무엇을 잡는가 | 소요 |
|---|---|---|---|
| ① 정적 확인 | `node --check`, Android `assembleDebug`, `python -m py_compile` | 문법·빌드 | 1분 |
| ② 서버 통합 | `tools/test/server-integration.js` | 배포 슬롯, 체크섬 판정, 재생 차단, 재부팅 명령, retain 여부 | 2~3분 |
| ③ 기기 건강 | `tools/test/device-health.js` | 발열·키오스크 해제·최근 재시작 판정, 기록 저장·중복 제거 | 1~2분 |
| ④ 대시보드 화면 | `tools/test/heartbeat-sim.js` + 브라우저 | 439대 상태별 그리드·알림·툴팁 | 수동 |
| ⑤ 에뮬레이터 E2E | `tools/test/emulator-e2e.js` | **실제 APK**: 파일 동기화, 체크섬 불일치, 다운로드 취소, 재생 오류, 원격 재시작/재부팅 | 15~25분 |
| ⑥ 리눅스 회귀 | WSL Ubuntu 복사본 | Windows와 다른 동작(프로세스 종료, 경로, 인코딩) | 상황별 |
| ⑦ 실기기 | 현장 폰 1~2대 → 블록 → 전체 | 디코더, One UI 정책, 발열, Wi-Fi 혼잡 | - |

> **원칙**: 서버 로직은 ②③으로, 앱 로직은 ⑤로, 플랫폼·하드웨어 특성은 ⑦로만 확인할 수 있습니다. 에뮬레이터에서는 디코더 고장, One UI 홈 정책, 실제 온도 센서를 재현할 수 없습니다.

## 2. 준비

```bash
cd tools/test
npm install            # aedes(테스트용 MQTT 브로커), mqtt, ws
```

- 포트 **3000(서버)과 1883(브로커)이 비어 있어야** 합니다. 개발 PC에서 Mosquitto나 서버를 띄워 놨으면 먼저 끕니다.
- 테스트가 실제 `server/src/server.js`를 띄웁니다. `server/node_modules`가 설치돼 있어야 합니다(`cd server && npm ci`).
- ⚠ **pCloud 등 동기화 폴더에서 테스트할 때**: 테스트가 잠깐 바꾼 `server/data`를 동기화 프로그램이 나중에 되돌리는 일이 있었습니다. 전후로 해시를 대조하세요.
  ```bash
  md5sum server/data/* > /tmp/before.txt
  # ... 테스트 ...
  md5sum server/data/* | diff /tmp/before.txt - && echo OK
  ```

## 3. 도구별 사용법

### 3.1 서버 통합 테스트 — `server-integration.js`
```bash
node tools/test/server-integration.js
```
- 구성: 로컬 브로커(aedes) + 실제 server.js + 가짜 폰 5대(MQTT 클라이언트).
- 임시 `server/distribute/`를 만들어 쓰고 끝나면 지웁니다. **이미 `server/distribute/`가 있으면 덮어쓰지 않고 중단합니다.** 실제 배포 파일이 있는 PC에서는 폴더를 잠시 옮긴 뒤 실행하세요.
- 확인 항목(23개):
  - 옛 체크섬 → 불일치 판정
  - 배포 중 재생·PLAY_TRIGGER 거부
  - CHECK_UPDATE는 미완료 폰에만 전달
  - config 발행은 폰당 1회
  - 재부팅 입력 검증, REBOOT_DEVICE non-retain 등
- 2026-10-07 레포 경로에서 23/23 통과 확인.

### 3.2 기기 건강 테스트 — `device-health.js`
```bash
node tools/test/device-health.js
```
- 가짜 heartbeat(온도·키오스크·lastExit)를 보내 서버 판정과 `data/device-events.json` 저장을 확인합니다. 서버를 재시작한 뒤의 유지, 중복 제거, [확인] 처리까지 봅니다.
- `server/data/device-events.json`이 이미 있으면 중단합니다(운영 기록 보호).
- 2026-10-07 16/16 통과 확인.

### 3.3 439대 heartbeat 시뮬레이터 — `heartbeat-sim.js`

### 3.4 에뮬레이터 E2E — `emulator-e2e.js`
**준비**
1. Android Studio에서 AVD 생성: API 34, Google APIs, x86_64 (개발 PC에서 쓴 이름은 `ms_test`). Play Store 이미지는 Device Owner 등록이 막힐 수 있으니 Google APIs 이미지를 씁니다.
2. 디버그 APK 빌드: `cd android && ./gradlew assembleDebug` (`JAVA_HOME` = Android Studio `jbr`)
3. 에뮬레이터 부팅 → `adb devices`에 보이는지 확인
4. `tools/test/clips/`에 시험 영상 준비(git 제외 폴더):

| 파일 | 용도 | 만드는 법(예) |
|---|---|---|
| `v1.mp4`, `v3.mp4`, `v5.mp4` | 서로 다른 작은 정상 영상 | `ffmpeg -f lavfi -i testsrc=size=480x854:rate=30 -t 5 -pix_fmt yuv420p v1.mp4` (색·길이를 바꿔 3개) |
| `v2.mp4`, `v4.mp4` | **느린 다운로드** 재현용 큰 영상(약 90MB) | 노이즈 입력 고비트레이트: `ffmpeg -f lavfi -i "nullsrc=s=480x854:r=30,geq=random(1)*255:128:128" -t 20 -c:v libx264 -b:v 36M -pix_fmt yuv420p v2.mp4` |
| `garbage.mp4` | 재생 불가 파일 | `head -c 3000000 /dev/urandom > garbage.mp4` |

**실행**
```bash
node tools/test/emulator-e2e.js
```

- 스크립트가 다음을 직접 처리합니다.
  - APK 설치
  - Device Owner 등록(`dpm set-device-owner --user 0 ...`, 에뮬레이터는 `--user 0`이 필요)
  - 저장소 권한, config 주입
- 에뮬레이터에서 서버 접근은 `10.0.2.2`를 씁니다.
- 시나리오:

  | | 확인 내용 |
  |---|---|
  | A | 첫 동기화 |
  | B | 배포 중 재생 거부 |
  | C | 같은 파일명 재배포 중 중복 요청 무시 |
  | D | 체크섬 불일치 시 옛 파일 유지 |
  | E | 다운로드 도중 재배포 시 이전 다운로드 취소 |
  | F | 재생 오류 보고·해제 |
  | G | 원격 앱 재시작 |
  | H | 원격 재부팅 → 부팅 자동 실행 |

- 2026-10-01 23/23 통과 기록이 있습니다. 레포로 옮긴 뒤에는 아직 실행하지 않았습니다(경로만 바뀜).

### 3.5 자동 복구 수동 시험 (에뮬레이터)
테스트 스크립트에는 아직 없고, 손으로 확인한 절차입니다.

```bash
# 홈 고정 확인
adb shell cmd package resolve-activity -c android.intent.category.HOME -a android.intent.action.MAIN
# 앱 프로세스 강제 종료 → 2초 안에 다시 뜨는지
adb shell am kill com.mediasphere.client ; adb shell pidof com.mediasphere.client
# 설정 화면을 앞에 띄운 채 두기 → 1~2분 안에 앱으로 돌아오는지(생존 알람)
adb shell am start -a android.settings.SETTINGS
# 재부팅 → 자동 실행 + 키오스크 잠금
adb reboot
```
Device Owner 앱은 `am force-stop`과 `am crash`가 시스템에 막힙니다(보호 패키지). 종료 시험은 `am kill`이나 프로세스 kill로 합니다.

### 3.6 리눅스(운영 OS) 회귀
- 운영은 Ubuntu이므로 프로세스 종료(ffmpeg 자식 프로세스), 경로, 파일 rename 동작을 WSL에서 확인합니다.
- **WSL의 ext4 영역**(`~/mstest` 등)에 레포를 복사해서 실행합니다. `/mnt/c`는 Windows 파일시스템이라 의미가 없습니다.
- 대표 사례: 영상 교체 취소 시 임시 폴더 정리, `.staging` → 배포 폴더 교체.

## 5. 새 기능을 만들 때의 검증 습관

1. 서버 기능 → `server-integration.js`처럼 **가짜 폰 N대**로 확인. 규모(439대)에서만 드러나는 문제는 시뮬레이터로 먼저 흉내 냅니다.
2. 앱 기능 → 에뮬레이터 E2E 시나리오를 하나 추가합니다.
3. 시간 동기화 관련 → 폰마다 시작 시각을 일부러 다르게 하는 경우(지연 도착, 중복 수신, 재접속)를 시나리오에 넣습니다.
4. 마지막으로 코드 리뷰 패스를 한 번 더 합니다. 이 프로젝트에서는 리뷰 단계에서 실제 버그가 여러 번 나왔습니다(`3fc25a9`).
