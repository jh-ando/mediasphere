# 08. 비슷한 프로젝트를 Claude Code로 시작하는 방법

> MediaSphere(2026-07 ~ 10, 세션 10개, 커밋 91개)를 Claude Code로 개발하면서 **잘 된 것과 돌아간 것**을 바탕으로 정리했습니다.
> 대상: 다수 기기 동기화, 설치형 미디어, 서버 + 앱 + 파이프라인이 섞인 프로젝트

---

## 1. 한눈에 보기

```
0일차  환경 준비 + CLAUDE.md 초안 (사람이 씀)
1주차  Phase 0: 작은 테스트 앱으로 성능 실측 → 핵심 사양 확정
       Phase 1: 1대 최소 경로(end-to-end) 완성
2주차~ Phase 2+: 대수를 늘리며(1→소수→수십→전체) 기능 추가
       매 기능: 조사 → 계획 → 구현 → 검증(테스트·리뷰) → CLAUDE.md 갱신 → 커밋
처음부터  원격 복구 수단 + N대 시뮬레이터 + 테스트 도구를 레포에
```

## 2. 0일차: 환경 준비

| 항목 | 이유 (이번 프로젝트에서 겪은 것) |
|---|---|
| 작업 폴더를 **클라우드 동기화(pCloud·OneDrive 등) 밖에** 두기 | 파일 잠금(EPERM), 충돌 사본, 테스트 중 바뀐 설정이 나중에 되돌아오는 문제가 있었음 |
| git 저장소 + 원격 + `.gitignore`(기기별 config, keystore, 배포 산출물, `node_modules`) | 기기별 config가 커밋될 뻔했음 |
| adb, Android SDK, ffmpeg, Node, Python을 PATH에 등록. Android Studio `jbr`을 `JAVA_HOME`으로 | Claude가 직접 빌드·설치·로그 확인을 하려면 명령줄에서 돌아가야 함 |
| 실기기 1대를 USB 또는 무선 디버깅으로 연결 | Claude가 adb로 스레드별 CPU를 직접 측정해 Phase 0 결론을 냄 |
| 에뮬레이터 AVD 1개 (Google APIs 이미지) | 실기기 없이 앱 E2E 검증. Device Owner를 쓸 거면 첫날 세팅 |
| 운영 OS가 다르면 그 OS 환경(WSL 등) | Windows 개발 + Ubuntu 운영 차이(프로세스 종료, cp949 인코딩) |
| release 서명 키를 **처음 만들 때** 백업 위치 결정 | 잃으면 이후 무선 업데이트 불가 |

## 3. CLAUDE.md 초안 (가장 중요)

Claude Code는 세션을 시작할 때마다 레포의 `CLAUDE.md`를 읽습니다. 이 파일이 곧 **프로젝트의 기억**입니다. 이번 프로젝트에서 세션이 10개로 나뉘었는데도 맥락이 이어진 이유가 이것입니다.

### 3.1 템플릿

```markdown
# <프로젝트명> — CLAUDE.md

## 프로젝트 정의
(무엇을, 몇 대로, 어떤 방식으로 - 3줄)

## 현재 개발 단계
(지금 Phase와 다음 할 일 - 매 단계 끝에 갱신)

## 수치 목표
- 동기화 오차 < 16ms, 드리프트 < 50ms ... (측정 가능한 숫자로)

## 확정 사항 / 미확정 사항
- 확정: 기종, 해상도, 배치표, 번호 규칙 ...
- 미확정: (명시해 두면 Claude가 임의로 정하지 않음)

## 아키텍처
- 통신 채널·포트·토픽 / 폴더 구조

## 프로토콜·API
(메시지 형식 - 구현하면서 계속 채움)

## 코드 컨벤션
- 언어별 스타일, 주석 언어(한국어), 로그 태그

## 주의사항
(실패에서 배운 것을 계속 추가 - 예: MulticastLock 없으면 UDP 수신 안 됨)

## 개발 단계 체크리스트
- [ ] Phase 0 ...

## 설계 노트
(중요한 결정과 그 이유, 기각한 대안)

## Git 규칙
- "커밋해줘"라고 할 때만 커밋. 자동 커밋 금지. (푸시도 요청 시에만)
```

### 3.2 운영 요령
- 처음에는 `/init`으로 초안을 받고 사람이 고쳐도 되지만, **확정·미확정 구분과 수치 목표는 사람이 직접** 적습니다.
- 기능을 하나 끝낼 때마다 "CLAUDE.md에 반영해줘"를 습관으로 합니다. 특히 **"왜 이렇게 했는지"**(설계 노트)와 **주의사항**이 다음 세션을 살립니다.
- 사람이 CLAUDE.md를 직접 고쳤으면 "md 파일 업데이트했으니 확인해줘"라고 알려 줍니다.
- 너무 길어지면 상세 내용은 `docs/`로 분리하고 CLAUDE.md에는 링크와 요약만 남깁니다.

## 4. 단계 진행법

### Phase 0: 실측으로 사양 정하기
```
갤럭시 A15 1대로 영상 재생 성능을 테스트하려고 해.
별도 테스트 앱을 만들어서 해상도·fps별 CPU, 온도, 드롭 프레임을 측정하고
하드웨어 디코딩 여부도 로그로 확인할 수 있게 해줘.
기기가 adb로 연결돼 있으니 직접 측정해서 표로 비교해줘.
```
→ 이번에는 여기서 "CPU는 초당 픽셀 처리량에 비례한다 → 480p 채택"이 나왔고, 이후 439대까지 같은 전제로 갔습니다.

### Phase 1: 1대로 끝까지
- 기능을 넓히기 전에 **서버 → 네트워크 → 기기 → 화면**의 최소 경로를 1대로 완성합니다.
- 동기화 같은 핵심 품질은 이 단계에서 **로그로 수치화**합니다("drift를 5초마다 요약 로그로 찍어줘").
- 임시 방편(예: 제어를 UDP 패킷에 임시로 실음)을 쓰면 CLAUDE.md에 "Phase 2에서 교체 예정"이라고 적어 둡니다.

### Phase 2 이후: 대수를 늘리며
- 1 → 16 → 100 → 439대로 키울 때마다 **새 종류의 버그**가 나왔습니다. 다운로드 폭주, 균일 격자 가정 붕괴, 상태 판정 오류 등입니다.
- 그래서 처음부터 요청할 것:
  - **"가짜 기기 N대를 흉내 내는 시뮬레이터와 통합 테스트를 만들어서 레포에 넣어줘"**
  - **"현장에 못 가도 복구할 수 있게 원격 재시작/재부팅, 부팅 자동 실행, 상태·종료 사유 보고를 설계해줘"**

## 5. 요청하는 법 (이번 프로젝트에서 효과가 컸던 패턴)

| 패턴 | 예 | 왜 |
|---|---|---|
| **조사와 수정 분리** | "코드 수정 없이 원인만 파악해줘" → 확인 → "이렇게 고쳐줘" | 잘못된 수정이 쌓이지 않음 |
| **증상·환경·사실을 주기** | "Android 14, 3버튼 내비, 펀치홀, 상단이 상태바 높이만큼 잘림" | 해결책을 지정해 3번 실패했던 문제가 증상을 주자 원인(컷아웃)에 닿음 |
| **로그는 원문 그대로** | logcat을 통째로 붙여넣기 | 로그의 날짜 하나로 "시계가 틀린 폰"을 찾음 |
| **가설 리셋** | "효과가 없어. 지금 가설은 버리고 원점에서 다시 봐줘" | 같은 가설에 계속 매달리는 것을 끊음 |
| **시안 먼저** | "UI 시안 2~3개 보여줘", "Q&A 초안 먼저 작성해줘" | 큰 UI·문서 작업의 방향을 일찍 맞춤 |
| **계획 먼저** | "구현 계획을 구체화해줘" (또는 Plan 모드) | 여러 파일에 걸친 작업의 범위·순서를 합의 |
| **검증 요구** | "할 수 있는 검증 다 했어? 코드 리뷰 포함해서. 에뮬레이터로도 돌려봐" | 리뷰·시뮬레이션 단계에서 실제 버그가 여러 번 나옴 |
| **운영 환경 확인** | "실제 우분투에서 돌려도 문제없겠지?" | Windows에서만 통과하던 것을 WSL로 다시 확인 |
| **결과 형태 지정** | "터미널 명령어만 줘, 코드는 고치지 마" | 원하지 않는 수정을 막음 |

**피할 것**
- 한 메시지에 서로 다른 큰 작업 여러 개 → 나눠서 요청합니다.
- 큰 변경을 검증 없이 연달아 쌓기 → 기능 단위로 검증하고 커밋합니다.
- 인수인계 메시지를 그대로 믿기 → 새 세션은 "CLAUDE.md와 코드로 현재 상태를 요약해줘"로 사실 확인부터 합니다(이번에 IP가 잘못 적혀 있었음).

## 6. 세션·기억 관리

| 도구 | 언제 | 이번 프로젝트 사례 |
|---|---|---|
| **새 세션** | 큰 단계가 바뀔 때, 주제가 바뀔 때 | Phase 0(성능), 대시보드 UI, 서버 부팅 설정을 각각 따로 진행 |
| **fork(갈래 세션)** | 같은 맥락에서 갈래를 나눌 때 | "UDP timecode server Phase 1 (fork)", Phase 3 fork. 같은 파일을 동시에 고치는 병렬 세션은 충돌이 나므로 영역을 나눔(서버 / 앱 / 대시보드) |
| **인수인계 메시지** | 세션을 닫기 전 | "다음 세션용 인수인계를 써줘: 완료, 미완료, 주의점, 다음 할 일" |
| **메모리** | 코드에 안 남는 사실 | "이건 기억해둬": 한국어 응답 선호, pCloud 간섭, 실기기 확인 대기 목록 |
| **문서(`docs/`)** | 사람도 읽어야 하는 것 | 프로토콜, 운영 매뉴얼, 이 문서 묶음 |

- 세션이 길어지면 앞부분이 요약되면서 세부가 흐려집니다. 중요한 결정은 **바로 CLAUDE.md나 문서에 적게** 합니다.
- 테스트 도구와 임시 스크립트는 세션 임시 폴더에 생기면 세션과 함께 사라집니다. 쓸모 있는 것은 **"레포의 tools/로 옮겨줘"**라고 요청합니다.

## 7. 커밋·리뷰 규칙

- CLAUDE.md에 "요청할 때만 커밋, 푸시도 요청 시"를 명시하고, 기능 단위로 "커밋 후 푸시해줘"를 요청합니다.
- 커밋에서 빼야 하는 파일(이번에는 로컬 버전 번호를 바꾼 `build.gradle.kts`)은 처음 한 번 말해 두면 이후에도 지킵니다. 메모리에 남겨 두면 더 확실합니다.
- 커밋 메시지는 Claude가 "무엇을 왜"까지 써 주므로, 나중에 **개발 정리 문서의 원자료**가 됩니다(이 문서 묶음도 커밋 91개 본문에서 만들었음).
- 큰 기능은 커밋 전에 리뷰 패스("코드 리뷰해줘")를 한 번 거칩니다.

## 8. 산출물 문서도 함께

이번 프로젝트에서 Claude Code로 함께 만든 문서입니다. 다음 프로젝트에서도 같은 시점에 요청하면 됩니다.

| 시점 | 문서 |
|---|---|
| 외부 업체 연동 논의 시 | 프로토콜 명세(UDP 타임코드, WebSocket 재생 신호, 프레임 프로토콜) - md + pdf |
| 운영 이관 전 | 운영 매뉴얼(docx/pdf, 대시보드 화면 캡처 포함), 대시보드 내 도움말 |
| 단계 마무리 | 개발 정리, 런북, OTA 절차, 장애 대응, 테스트 가이드, 하드웨어 기록, 인수인계 요약 (이 폴더) |

> 화면 캡처가 들어가는 문서는 "가짜 기기 시뮬레이터로 상태를 만들어 헤드리스 브라우저로 캡처해줘"라고 요청하면 실기기 없이 만들 수 있습니다.

## 9. 첫 세션 예시 프롬프트

```
CLAUDE.md를 읽고 프로젝트를 이해한 뒤 Phase 0 계획을 세워줘.
코드는 아직 쓰지 말고, 성능 검증 항목·측정 방법·판단 기준을 먼저 제안해줘.
기기는 adb로 연결돼 있어.
```

```
Phase 1을 시작하자. 서버 1개 + 폰 1대로 "PLAY 누르면 정확한 시각에 재생 시작,
재생 중 drift 보정"까지 끝까지 동작하게 만들어줘. drift는 로그로 수치화해서 보여줘.
끝나면 CLAUDE.md 체크리스트와 주의사항을 갱신해줘. 커밋은 내가 요청할 때만.
```

```
지금까지 만든 걸 할 수 있는 만큼 검증해줘. 코드 리뷰 포함, 가짜 기기 N대 통합 테스트,
에뮬레이터 E2E까지. 테스트 도구는 tools/test/에 넣고 실행법을 문서에 적어줘.
```

## 10. 체크리스트

- [ ] 작업 폴더가 동기화 폴더 밖에 있다
- [ ] CLAUDE.md에 수치 목표, 확정/미확정, Git 규칙이 있다
- [ ] Phase 0 실측 결과가 CLAUDE.md "검증 완료" 항목에 들어갔다
- [ ] 1대 end-to-end가 완성된 뒤 확장했다
- [ ] N대 시뮬레이터·통합 테스트가 레포에 있다
- [ ] 원격 재시작/재부팅/자동 실행/상태 보고가 설계에 들어 있다
- [ ] 서명 키 백업 위치가 정해졌다
- [ ] 기능마다 조사 → 구현 → 검증 → CLAUDE.md 갱신 → 커밋 순서를 지켰다
- [ ] 세션을 닫을 때 인수인계를 남겼다
