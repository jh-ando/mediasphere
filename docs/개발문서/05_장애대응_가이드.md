# 05. 장애 대응 가이드 (현장 기술자용)

> 운영자용 1차 대처는 운영 매뉴얼 v2의 12장과 대시보드 [? 도움말]에 있습니다. 이 문서는 그것으로 해결되지 않을 때 **서버·adb로 원인을 찾는** 단계입니다.
> 원칙: ① 범위 확인(전체 / 블록 / 1대) → ② 대시보드 신호 확인 → ③ 서버 → ④ 폰 순서로 내려갑니다. **앱 재시작 → 재부팅 → 현장 방문** 순서로 키웁니다.

---

## 1. 범위로 먼저 가르기

| 증상 범위 | 먼저 의심할 것 |
|---|---|
| **전체** 폰이 오프라인 | 서버 프로세스, Mosquitto, 서버 네트워크 |
| **전체** 싱크가 어긋남 | 서버 전원 모드(퍼포먼스인지), UDP 멀티캐스트 경로, 서버 과부하(영상 교체 인코딩 중인지) |
| **연속 번호 40여 대**가 같이 이상 | 그 블록을 담당하는 AP(`MEDIA_xx`). 번호 블록은 [02 런북](02_설치_구축_런북.md) 1장 |
| **같은 위도 줄**만 이상 | 그 줄의 전원·케이블 분배 |
| **1대**만 이상 | 그 폰(시계, 설정, 하드웨어, 디코더) |

---

## 2. 서버 점검 명령

```bash
systemctl status mediasphere-server mosquitto       # 📝 유닛 이름은 02 런북 2.4 확인
journalctl -u mediasphere-server -n 200 --no-pager  # 최근 서버 로그
journalctl -u mediasphere-server -f                 # 실시간
curl -s localhost:3000/api/state                    # 재생 상태
mosquitto_sub -h localhost -t 'wall/status/57' -C 1 # 57번 heartbeat 원문
mosquitto_sub -h localhost -t 'wall/#' -v           # 모든 MQTT 트래픽(많음)
df -h /home                                         # 디스크(영상 교체는 두 벌 필요)
nvidia-smi                                          # 영상 교체 인코딩 GPU
```

## 3. 폰 점검 명령 (adb)

무선 디버깅이 켜져 있으면 `adb connect <폰IP>:<포트>`, 아니면 USB로 연결합니다. 여러 대가 연결돼 있으면 `-s <시리얼>`을 붙입니다.

```bash
adb shell cat /sdcard/mediasphere/config.json        # deviceId·serverIp 확인
adb shell date                                       # ⚠ 시계가 크게 틀리지 않았는지
adb shell dumpsys package com.mediasphere.client | grep -E "versionCode|versionName"
adb shell dumpsys device_policy | grep -i -A2 "Device Owner"   # Device Owner 여부
adb shell ls -l /sdcard/mediasphere/videos/           # 영상 파일, .download 임시 파일 잔존 여부
adb shell sha256sum /sdcard/mediasphere/videos/P057.mp4
adb logcat -v time | grep -E "\[(MQTT|FileSync|Player|TimeSync|UDP|Health|Update|KeepAlive)\]|Player:|FATAL"
adb shell dumpsys thermalservice | head -30          # 발열 상태
adb shell am start -n com.mediasphere.client/.MainActivity   # 앱 수동 실행
adb shell reboot
```

> Windows PowerShell에서 `| findstr`을 쓰면 출력이 버퍼링돼 아무것도 안 나오는 것처럼 보일 수 있습니다. 필터 없이 보거나 Git Bash의 `grep`을 쓰세요.

## 4. 증상별 대응

### 4.1 오프라인(회색 칸)
1. 영상 교체·배포 중이면 다운로드 때문에 잠시 끊길 수 있습니다. **끝날 때까지 기다립니다.**
2. 몇 분째 계속이면: 대시보드 [앱 재시작]. 오프라인 폰에는 명령이 전달되지 않으므로, 실제로는 다음 단계가 필요한 경우가 많습니다.
3. 같은 블록이 함께 꺼졌으면 → AP 점검.
4. 1대만 꺼졌으면 현장에서 확인합니다.
   - 화면이 꺼짐 → 전원·케이블 확인(heartbeat가 끊기기 전에 "미충전" 알림이 있었는지).
   - 화면에 다른 앱이나 설정 화면이 보임 → 1~2분 기다리면 생존 알람이 앱을 다시 띄웁니다. 안 되면 왼쪽 위 5번 탭 → [앱으로 돌아가기].
   - 앱은 떠 있는데 오프라인 → Wi-Fi 연결 확인. 재부팅 직후라면 MQTT 첫 연결을 5초→30초 간격으로 재시도 중일 수 있습니다.
5. 그래도 안 되면 전원 버튼으로 재부팅합니다. 부팅 후 자동 실행됩니다.

### 4.2 화면 깨짐: 초록 바탕에 분홍 가로줄 / 검은 화면 (영상 모드에서만)
- 원인: 시스템 코덱 서비스(디코더) 고장. **앱 재시작으로는 풀리지 않고 재부팅해야 풀립니다.**
- 대응: 대시보드에서 그 번호를 [선택 재부팅] → 1~2분 뒤 온라인 복귀 확인 → 영상 재생 확인.
- `playerError`가 보고되는 경우도 있지만, **아무 오류 없이 깨지는 경우도 있으므로** 눈으로 확인하는 것이 가장 정확합니다.
- 재부팅 실패 사유 `NOT_DEVICE_OWNER`가 뜨면 그 폰은 Device Owner가 아닙니다. 현장에서 직접 재부팅한 뒤 재세팅을 계획합니다.
- 배포 직후에 자주 생긴다면 서버가 `e191745` 이후 빌드인지, 폰 앱이 그 이후 버전인지 확인합니다.

### 4.3 파일 불일치(테두리 표시)
- 셀 툴팁에 사유가 표시됩니다: `OLD_FILE`(옛 영상), `CHECKSUM_MISMATCH`, `DOWNLOAD_FAILED`, `RENAME_FAILED`.
- 배포가 끝난 뒤에도 남아 있으면 [배포]를 다시 누릅니다. 이미 맞는 폰은 건너뛰고 불일치 폰만 다시 받습니다.
- 계속 실패하면 그 폰의 저장 공간과 Wi-Fi 신호를 확인합니다(`adb shell df /sdcard`).
- 배포 진행률이 "0/1"처럼 이상하게 나오면 서버가 `a838842` 이후 빌드인지 확인합니다.

### 4.4 싱크가 어긋남
| 상황 | 확인 / 조치 |
|---|---|
| 전체가 조금씩 어긋남 | 서버 전원 모드 퍼포먼스, 서버 부하. 영상 [정지] → [재생]으로 다시 맞춤 |
| 1대만 영상이 어긋남 | `Player:` 로그의 drift 요약(5초마다). 계속 seek가 반복되면 Wi-Fi/멀티캐스트 수신 문제 → 재시작 |
| 1대만 텍스트·패턴이 어긋남 | **`adb shell date`로 시계 확인.** 몇 분 이상 틀렸으면 자동 시간 설정을 켜고 재시작. 그래도 다르면 기기 교체(실제 사례) |
| 영상은 정상인데 멀티캐스트 패킷이 안 옴 | `[UDP]` 로그. MulticastLock 획득 실패 또는 AP·스위치의 멀티캐스트 차단 |

### 4.5 발열 알림
- 기준: 발열 단계 3(심각) 이상 또는 배터리 45°C 이상.
- 1대만이면 설치 위치(통풍)·케이블을 확인합니다. 여러 대면 실내 온도와 운영 시간을 확인합니다.
- 발열로 앱이 죽으면 "최근 재시작"에 사유와 **종료 직전 온도**가 남습니다. 패턴(특정 위치, 특정 시간대)을 기록해 두세요.

### 4.6 최근 재시작(점선)
| 사유 | 의미 |
|---|---|
| `CRASH`, `ANR` | 앱 오류 → 상세(`detail`)를 개발자에게 전달 |
| `LOW_MEMORY`, `SIGNALED` | 시스템이 정리함(발열·메모리). 직전 온도 확인 |
| `DEVICE_REBOOT` | 기기 재부팅(전원 차단, 시스템 재시작) |
| 의도한 종료(RESTART/REBOOT/UPDATE) | 원격 명령이나 OTA로 인한 종료. 알림에 포함되지 않음 |

내용을 확인했으면 [확인]을 눌러 알림에서 뺍니다(기록은 남음).

### 4.7 키오스크 해제
현장 정비 중인 폰입니다. 정비가 끝나면 [앱으로 돌아가기]를 누르거나 10분 뒤 자동으로 돌아옵니다. 아무도 정비하지 않는데 해제 상태라면 누군가 화면 구석을 만졌을 수 있습니다.

### 4.8 버전 다름
OTA가 덜 끝난 폰입니다. [03_릴리스_OTA_절차](03_릴리스_OTA_절차.md) 5장을 보세요.

### 4.9 영상 교체 실패
- 대시보드 로그(오류 시 자동으로 펼쳐짐)의 마지막 줄을 봅니다.
- 흔한 원인:

  | 원인 | 확인 |
  |---|---|
  | 디스크 부족 | `df -h` |
  | GPU·드라이버 | `nvidia-smi` |
  | 원본 손상 또는 코덱 미지원 | `ffprobe` |
  | 영상 모드가 아님 | |

- 실패하거나 취소해도 **배포 폴더와 폰 영상은 이전 그대로**입니다(임시 폴더에서 인코딩하기 때문).
- "지난 교체의 임시 폴더를 지우지 못했습니다"가 나오면 서버에서 `server/distribute/.staging`이 남아 있는지 확인하고, 인코딩 프로세스가 없는 것을 확인한 뒤 지웁니다.

### 4.10 모드 전환·재생 버튼이 안 눌림
정상 동작입니다. 무언가 실행 중이거나 교체·배포 중입니다. 노란 안내를 보고 먼저 정지하세요.

### 4.11 운영 시간인데 재생이 안 됨
- 타이머는 **경계 시각에만** 동작합니다. 운영 중에 수동으로 정지했다면 다음 경계까지 그대로입니다.
- 시작 시각에 배포 중이었다면 배포가 끝난 뒤 재생합니다.
- 휴관 요일 설정과 서버 시계(`date`)를 확인합니다.

### 4.12 외부 업체 신호(PLAY_TRIGGER)가 무시됨
서버 로그에서 `[WS] PLAY_TRIGGER` 줄을 찾습니다. 다음 경우에는 의도적으로 무시(ERROR 응답)합니다.
- 배포·교체 중
- 절전 중
- 운영 시간 밖
