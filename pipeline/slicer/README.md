# MediaSphere 영상 분할 파이프라인

Phase 3 평면 15분할과 운영 구체 499분할을 **하나의 구조**로 처리한다.

```
gen_tiles.py  flat   ─┐
                      ├→ tiles.json ─→ slice_video.py ─→ P001.mp4 … + manifest.json
gen_tiles.py  sphere ─┘
```

등장방형 영상에서 위도/경도 구간을 잘라내면 그것도 직사각형이다. 폰 하나가 먹는
각도가 3.96° × 8.59°로 작아 사다리꼴 왜곡도 무시할 수준이다. 그래서 **좌표 생성기만
갈아끼우고 crop 엔진·Android·서버 배포는 그대로** 쓴다.

---

## 파일 목록

```
gen_tiles.py            좌표 생성기 (평면/구체)
slice_video.py          FFmpeg 분할기
preview_rig.py          정지 프레임으로 리그 배치 목업 생성
tiles/                  미리 생성해둔 좌표 파일
```

### 평면 15분할 — 리그 피치 110 × 200mm 기준

물리 550 × 600mm (11:12 세로형), gap-x 0.371 / gap-y 0.250

| 파일 | 원본 해상도 | 폰당 픽셀 | 용도 |
|---|---|---|---|
| `flat15_native.json` | 8584 × 9366 | 1078 × 2340 | 화질 손실 없음. 80Mpx라 무거움 |
| `flat15_half.json` | 4292 × 4682 | 538 × 1168 | 균형점 |
| `flat15_1080p.json` | 1080 × 1178 | 134 × 294 | **1080p 샘플용** |
| `flat15_like16k.json` | 1336 × 1460 | 168 × 364 | 16K 구체 화질 재현 |
| `flat15_like8k.json` | 668 × 730 | 84 × 182 | **8K 구체 화질 재현** |
| `flat15_like4k.json` | 334 × 366 | 42 × 90 | 4K 구체 화질 재현 |

`like*` 는 실제 구체에서 보일 화질을 평면 리그에서 미리 확인하기 위한 것이다.
평면은 원본의 47%를 쓰고 구체는 33%만 쓰기 때문에, **같은 원본 해상도라도
평면 샘플이 실제보다 좋게 보인다.** 클라이언트 보고용 화질 자료는 `like8k` 로 뽑을 것.

### 구체 499분할 — Phase 4 대비

| 파일 | 원본 해상도 | 적도 폰 픽셀 |
|---|---|---|
| `sphere499_8k.json` | 7680 × 3840 | 84 × 182 |
| `sphere499_4k.json` | 3840 × 1920 | 42 × 92 |

위도별 배치(적도 50 / ±11.25° 50 / ±22.5° 50 / ±33.75° 50 / ±45° 40 /
±56.25° 25 / −67.5° 15 / −78.75° 4 = 499대)가 `gen_tiles.py` 에 내장돼 있다.

경도 0° 경계를 넘는 타일 13개는 `wrap: true` 로 표시되고 `slice_video.py` 가
좌우 두 조각을 자동으로 이어붙인다.

## 사용법

```bash
python3 slice_video.py -i master.mp4 -t tiles/flat15_1080p.json -o out/
```

**원본 해상도와 비율은 아무거나 넣어도 된다.** 알아서 가운데를 잘라 비율을 맞추고
tiles.json 해상도로 스케일한 뒤 분할한다.

```
[i] 비율 보정 crop 1920x1080 → 988x1080 (center 기준, 화면의 48.5% 잘림)
[i] 원본 1920x1080 → 668x730 (crop, lanczos)
[i] 타일 15개 / 출력 1080x2340 / 인코더 libx264 / 동시 5개
```

### 옵션

| 옵션 | 설명 |
|---|---|
| `--encoder hevc_nvenc` | RTX 5060 Ti 하드웨어 인코딩 (CPU 대비 5~10배) |
| `-j 8` | 동시 인코딩 수. NVENC는 세션 제한이 있으니 4~8 권장 |
| `--quality 20` | CRF/CQ. 낮을수록 고화질 |
| `--gop 30` | 키프레임 간격. **동기화 seek 정확도에 직결** |
| `--fit stretch` | 비율 안 맞을 때 자르지 말고 늘리기 (기본은 crop) |
| `--anchor top` | crop 기준 위치 (center/top/bottom/left/right) |
| `--prescale WxH` | 스케일 목표를 직접 지정 (기본은 tiles.json 값) |
| `--scale-flags lanczos` | 스케일 알고리즘 |
| `--fps source` | 프레임레이트 리타이밍 끄기 (기본은 auto) |
| `--output-size fit` | 타일 원본 크기로 인코딩 (기본은 1080x2340 업스케일) |
| `--only P001,P008` | 특정 타일만 (디버깅용) |
| `--dry-run` | 실제 인코딩 없이 ffmpeg 명령만 출력 |

### 비율별 crop 손실

| 입력 | crop 결과 | 손실 |
|---|---|---|
| 1100 × 1200 | 그대로 | 0% |
| 1080 × 1080 | 988 × 1080 | 8.5% |
| 720 × 1280 | 720 × 786 | 38.6% |
| 1920 × 1080 | 988 × 1080 | 48.5% |
| 3840 × 2160 | 1976 × 2160 | 48.5% |

**가로형 원본(16:9)은 절반이 날아간다.** 리그가 11:12 세로형이기 때문이다.
가로 영상밖에 없으면 `--fit stretch` 로 왜곡을 감수하거나 리그를 다시 짜야 한다.
영상을 새로 만든다면 **1100 × 1200** 이 정확히 11:12라 깔끔하다.

가운데 기준으로 자르므로 **중요한 내용은 화면 중앙에 두고 제작할 것.**

### 출력 해상도

기본값은 tiles.json 의 `output` 값, 즉 **1080x2340** 이다. 134x294 로 잘라낸 뒤
폰 화면 크기까지 미리 늘려서 인코딩한다. 폰 하드웨어 스케일러보다 lanczos 가
낫고, 모든 파일 해상도가 같아 디코더 경로가 균일하다는 이유였다.

**대신 파일이 12배 커지고 디코딩 부담도 그만큼 는다.**

| `--output-size` | 결과 | 5초 클립 1개 | 인코딩 |
|---|---|---|---|
| `tiles` (기본) | 1080x2340 | 292KB | 4.6초 |
| `fit` | 136x294 | 24KB | 0.7초 |
| `540x1170` | 540x1170 | 116KB | 1.4초 |

**499대 배포에는 `fit` 을 권한다.** Wi-Fi 로 파일을 뿌려야 하고 A15 의 Helio G99
로 디코딩해야 하는데, 12배 차이는 그대로 배포 시간과 발열로 돌아온다.
12배 확대 구간에서는 lanczos 의 이점도 거의 사라진다(오히려 링잉이 생긴다).

`fit` 은 폰 화면 비율을 유지하면서 타일보다 작아지지 않는 최소 크기를 쓴다.
구체 타일은 위도마다 폭이 달라 결과도 8종으로 나뉜다.

```
±0.00° → 84x182     ±45.00° → 120x260
±11.25° → 86x186    ±56.25° → 150x328
±22.50° → 90x198    ±67.50° → 220x476
±33.75° → 102x220   ±78.75° → 432x936
```

**Android 쪽은 수정 없이 그대로 재생된다.** 다만 ExoPlayer 의 resize mode 가
화면을 채우도록 설정돼 있는지 한 번 확인할 것.

### 프레임레이트 정합

UDP 타임코드가 **30fps 고정**이라 원본이 29.97fps(30000/1001)면 계속 어긋난다.

```
   17초 재생 →   17ms  (0.5 프레임)
   1분 재생 →    60ms  (1.8 프레임)
  10분 재생 →   599ms  ( 18 프레임)
   1시간 →     3596ms  (108 프레임)
```

기본값 `--fps auto` 가 `setpts` 로 리타이밍해서 정확히 30fps 로 맞춘다.
프레임을 중복·누락시키지 않고 재생 속도를 0.1% 올리는 방식이라 화질 손실이 없다.

```
[i] 프레임레이트 29.970 → 30 리타이밍 (재생 속도 +0.10%, 프레임 중복/누락 없음)
```

원본 프레임레이트를 유지하려면 `--fps source`.

### GOP 주의

`--gop` 값이 크면 ExoPlayer `seekTo()` 가 가장 가까운 키프레임으로 붙으면서
폰마다 시작 프레임이 어긋날 수 있다. 30fps 기준 **30 이하** 권장,
정밀 동기화가 필요하면 `--gop 1`(all-intra)까지 낮출 수 있다. 대신 용량이 크게 는다.

## 출력물

```
out/
  P001.mp4 … P015.mp4     폰별 영상 (1080x2340)
  manifest.json           id ↔ 파일 ↔ 좌표 메타
```

`manifest.json` 을 각 폰 `config.json` 배포에 쓴다. APK는 전부 동일하고
폰은 자기 `id` 에 해당하는 파일만 받으면 된다.

## 좌표 파일 새로 만들기

리그 피치가 바뀌면:

```bash
python3 gen_tiles.py flat --pitch 120x210 --downscale 2 -o tiles/new.json
```

실측 폰 중심간 거리(mm)만 넣으면 원본 해상도와 gap 을 자동 계산한다.
`--downscale 2` 는 네이티브 대비 1/2.

구체 배치가 바뀌면:

```bash
python3 gen_tiles.py sphere --source 7680x3840 --rows-file rows.json -o tiles/new.json
```

`rows.json` 은 `[[56.25,25],[45,40],[33.75,50], …]` 형식.

생성 시 확대율과 원본 활용률을 리포트하므로 해상도 판단 근거로 쓴다.

## 리그 배치 미리보기

인코딩 전에 정지 프레임 한 장으로 실제 배치를 확인한다. 폰 사이 간격까지 반영된다.

```bash
ffmpeg -ss 6 -i master.mp4 -frames:v 1 frame.png
python3 preview_rig.py frame.png tiles/flat15_like8k.json preview.png 132 crop
```

인자는 `<원본 프레임> <tiles.json> <출력 png> [타일 표시폭] [crop|stretch]`.
`like8k` 로 뽑으면 실제 구체에서 보일 화질을 그대로 확인할 수 있다.

## 재조립 검증

분할이 맞는지 눈으로 확인:

```bash
mkdir -p verify
for i in $(seq -w 1 15); do
  ffmpeg -y -i out/P0$i.mp4 -vf "scale=216:468" -frames:v 1 verify/P0$i.png
done
```

원본과 이어지면 좌표가 맞은 것이다. 구체는 `--only` 로 같은 행의 인접 타일
몇 개만 뽑아 경계가 이어지는지 본다.

## 알려진 제약

- **역변환 보정 미적용** — 현재는 등장방형 직사각 crop 이다. 폰 각도가 작아
  왜곡이 미미하지만, 정밀하게 가려면 `v360` 필터로 각 폰 시점을 rectilinear
  투영해야 한다. 그때는 tiles.json 에 `projection: rectilinear` 를 추가하고
  `slice_video.py` 의 crop 을
  `v360=e:rect:yaw=..:pitch=..:h_fov=..:v_fov=..` 로 교체한다. 구조는 그대로다.
- **아틀라스 팩킹 미구현** — 499개 파일 대신 타일을 한 장에 팩킹하면 같은 픽셀
  예산으로 3배 화질이 나온다(등장방형은 극지방과 폰 사이 간격에 67%를 낭비).
  tiles.json 스키마에 `atlas_cell` 을 추가하는 방향으로 확장 가능.
- NVENC 동시 세션 제한이 있으니 `-j` 를 무작정 올리지 말 것.
